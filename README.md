# Каталог предметов

Статическая страница на чистом JS (ES-модули, без сборки и без внешних библиотек). Три режима:

1. **Каталог** — поиск, фильтры, сортировка, карточки, подробности.
2. **Сравнение версий** — что изменилось между двумя файлами `handler.json` (новые / удалённые / изменённые предметы, с цветовой разметкой).
3. **Фоторежим** — готовые PNG-карточки 1720×1280 для поста: характеристики предмета, разбор одного изменения, итоговая статистика обновления.

## Структура

```
item_catalog/
├── index.html   — разметка, две вкладки
├── style.css    — стили (тёмная тема)
├── core.js      — утилиты, нормализация и разбор JSON, экспорт CSV/JSON
├── store.js     — общее состояние (чтобы вкладка «Сравнение» видела данные «Каталога»)
├── diff.js      — движок сравнения двух наборов предметов (без DOM)
├── photo.js     — рендер PNG-карточек на <canvas> и окно предпросмотра
├── catalog.js   — логика вкладки «Каталог»
├── compare.js   — логика вкладки «Сравнение»
├── main.js      — точка входа, переключение вкладок
├── handler.json — ваш файл с данными (положить рядом)
└── README.md
```

## Как запустить

1. Скачайте `handler.json` и положите его в одну папку с `index.html`.
2. Откройте страницу:
   - **GitHub Pages** — самый удобный вариант, никаких дополнительных настроек.
   - **Локальный сервер** — `python -m http.server 8000` в папке проекта, затем `http://localhost:8000`. Нужен именно сервер, а не двойной клик по файлу: страница — это ES-модули (`type="module"`), а браузеры не позволяют им загружаться по протоколу `file://`.
   - Если автозагрузка `handler.json` всё же не удалась (например, нет сервера), страница сама покажет поле для ручного выбора файла — ничего не сломается.

## Вкладка «Сравнение версий»

1. **База (старая версия)** — выберите один из двух источников:
   - «Текущие данные каталога» — то, что уже загружено во вкладке «Каталог» (кнопка активируется, когда там что-то загружено);
   - «Загрузить файл…» — любой другой `handler.json`, например вчерашний снимок.
2. **Новая версия** — выберите свежий `handler.json`, скачанный после обновления игры.
3. Нажмите **«Сравнить версии»**.

Результат — список только отличий, каждое окрашено по смыслу:
- 🟡 **жёлтая полоса** — новый предмет, которого раньше не было;
- 🔴 **красная полоса** — предмет удалён из новой версии;
- 🔵 **синяя полоса** — у предмета изменились характеристики; внутри карточки каждое поле показано как «было → стало», число покрашено **зелёным**, если выросло, и **красным**, если уменьшилось (буквально по значению, без оценки «хорошо/плохо»). Для улучшений показывается, какой именно уровень изменился и на сколько — в значении и в цене золота.

Сопоставление предметов идёт по `item_id`. Если в обновлении улучшение не просто изменили, а переименовали, страница покажет это как «удалено старое + добавлено новое» — переименования различить автоматически нельзя.

Фильтры позволяют оставить только новые/удалённые/изменённые, по типу или по тексту, сортировать по ID, по названию или «сильнее всего изменились». Экспорт CSV/JSON выгружает именно то, что сейчас видно на экране (с учётом фильтров) — в CSV одна строка на одно отличие (одно поле или один уровень улучшения), удобно сортировать и считать в таблицах.

## Фоторежим

Кнопка с 📸 есть в трёх местах:
- в карточке предмета (вкладка «Каталог») — характеристики предмета целиком;
- у каждой строки в списке сравнения — разбор конкретного изменения (было → стало);
- кнопка «Итоговая статистика» над списком сравнения — сводная картинка обновления: сколько было/стало предметов, сколько новых/удалённых/изменённых, разбивка новых и изменённых по типам, топ-5 изменений цены.

Все картинки — ровно **1720×1280**, тёмная тема, без фотографии самого предмета (иконки лежат на другом домене и могут не отдавать CORS-заголовки — это снова сломало бы экспорт, как и прямой запрос к API игры). Вместо иконки — цветная плашка с первой буквой названия, цвет зависит от типа предмета. Все числа и подписи крупные и подписаны, чтобы скриншот/картинку можно было выкладывать без дополнительной обработки.

По клику открывается окно предпросмотра с кнопкой «Скачать PNG».

## Обновление данных

Замените `handler.json` новым файлом с тем же именем и обновите страницу. Код менять не нужно.

## Устойчивость к данным

- Пропущенные поля (`item_buy_amount`, `upgrades`, `item_type.name` и т.п.) заменяются значениями по умолчанию.
- Предметы без названий получают название `Предмет #ID`.
- Некорректные записи пропускаются, их количество выводится в шапке.
- Битые картинки в каталоге скрываются, вместо них — буква-заглушка.
- Все строки из файла экранируются перед выводом, разметка в данных не выполняется.
- Любая ошибка (в т.ч. при сравнении и при генерации фото) показывается в статусной строке; остальная страница продолжает работать.
